Developer guide

Build with window.llm

Add AI to your website in a few lines — using the visitor's own models and keys, not yours. No SDK to install, no backend to run, no API keys in your code. This guide takes you from a single <script> tag to streaming, tools, and embeddings.

Prefer the exact contract? This is the friendly tour. The normative reference — every interface, dictionary, and error code — is the WindowLLM specification.

01What is window.llm?

window.llm is a browser API for talking to Large Language Models. The twist: the user brings the model. They configure their providers once at their vault (the reference vault lives at windowllm.org), and any site can then call window.llm to use them.

Two properties make it different from calling a provider yourself:

🔑 Keys stay sealed

API keys never leave the vault origin. Your page sends prompts and gets results; it never sees a credential — even under XSS.

🔌 One API, any provider

Anthropic, OpenAI, Gemini, OpenRouter, or local models via Ollama. You request capabilities; adapters normalize the rest.

Under the hood your <script> loads a tiny client (llm.js) that talks to a hidden vault iframe over postMessage. You don't have to think about any of that — you just call methods and await results.

02What you can build

The same handful of calls scales from a weekend button to things that were previously impractical for a frontend to attempt. A ladder, roughly from easiest to most ambitious:

1

Explain & summarize Basic

A “Summarize this,” “Explain this error,” or hover-to-define button. One complete() call behind a click — the fastest way to put AI on a page, shippable this afternoon.

Leans on: a single completion.

2

Compose & transform text Basic

Draft replies, rewrite for tone, translate, or fix grammar right inside your text fields. Stream the result so it types out live and feels instant.

Leans on: streaming.

3

Turn messy input into clean data Everyday

Paste a receipt and get itemized JSON; drop in an email and get a calendar event; convert free text into a filled-in form. You receive typed objects, not prose, so the rest of your app just works.

Leans on: structured output.

4

Semantic search over the user's own data Powerful

A notes app, a docs reader, a local-first tool: embed the user's content in the browser and rank by meaning instead of keywords. Their documents — and the vectors — never touch your server.

Leans on: embeddings.

5

An in-app copilot that can act Powerful

Expose your app's actions as tools and let people drive by intent: “move this to next sprint,” “chart revenue by region,” “email the team.” The model calls your functions; your code stays in control of what actually happens.

Leans on: tool calling + sessions.

6

Privacy-critical & regulated work Advanced

Health, legal, finance, journalism: the prompt goes from the user straight to their provider — your servers never see the content, and you hold no keys and no liability for them. Pair it with a local model (Ollama, via the extension) for fully on-device, offline AI.

Leans on: the vault's key isolation + local models.

7

Real AI on a static site, at zero cost to you Unlock

Because users bring their own keys, indie apps, open-source tools, and static/JAMstack sites can ship genuine AI features with no backend, no inference bill, and no per-user cost. The feature you couldn't afford to run for everyone is suddenly free to offer.

Leans on: the whole model — no server, no keys, no meter.

Notice the pattern: each rung reuses the same primitives, and the most valuable ones lean hardest on the property a normal integration can't offer — the user's keys and data never leave their control.

03Quickstart (about 60 seconds)

Drop in the client, check it's available, open a session, complete a prompt.

html
<!-- Load the client from the vault origin -->
<script src="https://windowllm.org/llm.js"></script>
javascript
// Always feature-detect: the API is absent when nothing is configured.
if (!window.llm) {
  // Point the user at windowllm.org to set up their vault.
  return;
}

const session = await window.llm.requestSession();
const result = await session.complete("Explain WindowLLM in one line.");

console.log(result.message.content);
// → "A browser API that lets sites use your own AI models, keys sealed."

The first requestSession() triggers a one-time consent prompt in the vault. Once the user grants it, calls resolve immediately. That's the whole happy path — everything below is refinement.

04Sessions & memory

A session is a conversation. It remembers everything you send until you reset or destroy it, so multi-turn chat just works.

javascript
const session = await window.llm.requestSession({
  systemPrompt: "You are a concise assistant.",
  settings: { temperature: 0.7, maxTokens: 800 }
});

await session.complete("My name is Alice.");
const r = await session.complete("What's my name?");
// → "Your name is Alice."  (context is preserved)

const branch = await session.clone();  // fork the conversation
session.reset();    // clear history, keep the system prompt
session.destroy();  // release it when you're done

Pick a model, or don't. Omit model and the vault chooses a capable default. Or target one explicitly with { model: "anthropic/claude-3-opus" }, or by requirements — see Models & capabilities.

05Streaming

For a typing-effect UI, use stream(). It returns an async iterable of chunks; each text chunk carries both the new delta and the full accumulated text, so you can just assign the latter.

javascript
for await (const chunk of session.stream("Write a haiku about sovereignty.")) {
  switch (chunk.type) {
    case "text":
      output.textContent = chunk.accumulated;
      break;
    case "done":
      console.log("tokens:", chunk.result.usage.totalTokens);
      break;
  }
}

Chunk types are text, tool_call, usage, error, and done. The final done chunk hands you the complete result — no manual reassembly needed.

06Tool calling

Give the model functions it can ask you to run. Declare them with JSON-Schema parameters; when the model wants one, you'll get a finishReason of "tool_use" and the calls to execute. Run them, hand the results back, and let the model continue.

javascript
const weather = {
  name: "get_weather",
  description: "Get current weather for a city",
  parameters: {
    type: "object",
    properties: { city: { type: "string", description: "City name" } },
    required: ["city"]
  }
};

const session = await window.llm.requestSession({ tools: [weather] });
let result = await session.complete("What's the weather in Tokyo?");

if (result.finishReason === "tool_use") {
  const call = result.toolCalls[0];
  const data = await getWeather(call.arguments.city);

  result = await session.complete([{
    role: "tool",
    toolCallId: call.id,
    content: data,
    success: true
  }]);
}
console.log(result.message.content);  // model's final answer

Loop for multi-step tools. A model may call several tools in a row. Keep feeding results back while finishReason === "tool_use", and stop when it returns "complete".

07Local page tools

Let a tool-capable model query the current document with normal CSS selectors. WindowLLM executes every operation locally and sends only a serialized result to the provider. The provider never receives an Element or arbitrary JavaScript access.

javascript
const session = await window.llm.requestSession({
  page: {
    access: "read-write",
    scope: "#editor"
  },
  systemPrompt: "Use the page tools to inspect and update only the requested elements."
});

const result = await session.run(
  "Find #draft-status, change its text to Ready, and report what changed."
);

console.log(result.steps);
console.log(result.stopReason);
console.table(result.pageToolExecutions);

Use access: "read" for querySelector() and querySelectorAll() only. Read-write mode also exposes controlled click, value, text, and application-state attribute operations. Attributes are restricted to data-*, aria-*, and title. Mutation calls use opaque references returned by an earlier query, so the model never manufactures a DOM object.

Keep the scope narrow. A CSS scope is resolved once per operation and bounds every query and write. Sensitive form values remain redacted for the lifetime of their element reference, and agent runs return with stopReason: "max_steps" before executing a terminal tool batch. The default limit is eight model turns.

Page tools are available only through run(). They are not advertised by complete() or stream(), and page access cannot currently be combined with site-defined tools in one session.

Open the live page-tools workbench to run read-only and read-write tasks against a visible local document. The workbench shows every selector, element reference, result, and DOM change as it happens.

08Structured output

Need JSON you can parse instead of prose? Ask for it with responseFormat. On models that report the jsonMode capability, you can also pass a schema.

javascript
const session = await window.llm.requestSession({
  responseFormat: {
    type: "json",
    schema: {
      type: "object",
      properties: {
        title: { type: "string" },
        tags:  { type: "array", items: { type: "string" } }
      },
      required: ["title"]
    }
  }
});

const r = await session.complete("Summarize this article as title + tags: ...");
const data = JSON.parse(r.message.content);

09Embeddings

For search and similarity, request an embedding session. Vectors come back as a Float32Array — ready for a dot product.

javascript
const embedder = await window.llm.requestEmbedding({ dimensions: 1536 });

const one = await embedder.embed("Hello world");
const many = await embedder.embedBatch(["apple", "orange", "car"]);

console.log(one.vector.length);  // 1536
embedder.destroy();

10Permissions

Access follows the familiar Web Permissions pattern. query() checks state without prompting; request() may show the user a consent dialog. This lets you explain why before the prompt appears.

javascript
const status = await window.llm.permissions.query({ name: "chat" });

if (status.state === "prompt") {
  await showWhyWeNeedAI();               // your explainer UI
  await window.llm.permissions.request({ name: "chat" });
}

status.onchange = () => {
  if (status.state === "denied") showFallback();
};

States are "granted", "denied", and "prompt". Users can revoke access at any time from their vault — so always handle the denied path gracefully.

11Models & capabilities

Don't hard-code a model. Ask what the user has, or describe what you need and let the vault pick.

javascript
// Coarse check before you build UI:
if (window.llm.capabilities.has("vision")) enableImageUpload();

// List everything the user configured:
const models = await window.llm.models.list();

// Or match by requirement and take the best:
const [best] = await window.llm.models.match({
  capabilities: { required: ["tools"], preferred: ["vision"] },
  limits: { minContextWindow: 100000 },
  preference: "quality"
});

Capabilities include chat, streaming, tools, vision, embeddings, jsonMode, systemPrompt, multiTurn, audioInput, and audioOutput.

12Handling errors

Everything rejects with an LLMError carrying a stable code. Some are worth retrying — check error.retryable, and honor error.retryAfter (milliseconds) on rate limits.

javascript
try {
  const r = await session.complete(input);
} catch (err) {
  switch (err.code) {
    case "NOT_CONFIGURED":   showSetupLink();          break;
    case "PERMISSION_DENIED": showFallback();          break;
    case "RATE_LIMITED":      await wait(err.retryAfter); break;
    default:                   reportUnexpected(err);
  }
}
